# Phase 4 Image-to-Description Protocol

本协议用于具备真实视觉输入能力的宿主。`scripts/image_description.py` 只复核结构化观察并生成报告，不能读取图像像素或自动识别人脸特征。

## 输入与范围

1. 确认用户对图像的使用权限、分析目的、是否涉及真实案件，以及输出范围。
2. 记录图像资产 ID、来源、取得时间、文件哈希、是否可能镜像、所见视角、裁切和处理情况。用户图片与原始记忆须分开保存。
3. 无视觉输入能力时停止图像观察，说明只能提供人工观察表或接收用户文字描述。

## 图像质量门控

在描述任何面部特征前，填写 `image_quality_report`：分辨率/细节、清晰度、光照、噪声、伪影、遮挡、头姿、畸变、裁切。若任一因素严重影响所需细节，降低观察范围并写明受影响组件；整体不适用时不得输出确定的面部结构。

视觉上的局部纹理突变、重复区域、边缘不连续、异常平滑或光照/噪声不一致，可以登记为“可疑线索”。这不等于图像真实性认证；必要时交由数字图像专家复核（S23）。

## 观察顺序

1. 先记录 `viewpoint`（正面、左/右斜面、左/右侧面或未知）、表情、头部姿态和镜像状态。镜像未知时使用图像坐标系左右。
2. 先观察整体轮廓与构成（F02、F03），再按 `F01`–`F19` 顺序检查。每个组件给出“可见且有观察”“不可观察”“未知”或“不适用”；不以空值默认正常/对称。
3. 每项观察记录对应的 `feature_id`、描述、可见性、置信等级、侧别、视角、图像区域证据、S01/S02 等知识引用及限制。
4. 在组件观察后才记录相对空间关系和不对称项。仅使用定性相对描述；不从单张非标准照片推算精确人体测量。
5. 对遮发、侧面缺失、模糊、低照度、表情造成的外观变化保持未知。不得根据图像推断身份、犯罪性、性格、健康诊断或敏感属性。

## 生成用关键锚点

在进入提示词编译前，单独检查以下项目。每一项必须记录为“有观察”“不可观察”或“未知”，不得留空，也不得用人群平均值补全：

- 整体脸部轮廓与宽度分布（F02.C02）；
- 五官配置和主要间距（F03.C01）；
- 眼距、眼线位置、眼裂及眉眼关系（F07、F06）；
- 鼻部轮廓和鼻翼宽度（F09）；
- 嘴宽、上唇/下唇唇红高度、唇红缘、口裂与口角（F11）；
- 颧部、下颌和下巴的可见轮廓（F08、F12）；
- 肤色明度与冷暖（F01，仅作图像内观察）；
- 发际线（F04.C06，清晰可见时）；
- 用户确认的年龄外观和性别呈现线索（只作渲染线索）。

`can_describe` 表示图像和证据足以输出观察报告；`likeness_prompt_readiness` 表示关键整体和局部锚点已具备，二者不能混用。缺少锚点时可以继续输出有限描述，但应在报告中列出缺项。

上唇的“厚”必须进一步区分唇红可见高度、软组织丰满度和外突。眉弓外观、眉毛毛发、眼裂、眼睑和内外眦也分别记录。详情见 `knowledge/description/`。

中文术语参照 CN03（SF/T 0125—2021 §4.2.3–4.2.4，官方链接见 `knowledge/source_manifest.yaml`）：眉分开记录走向、浓淡、疏密和眉头/眉梢；口分开记录上唇、下唇的厚薄、口裂线和开闭状态；五官配置记录位置及横向/纵向比例。使用这些维度作定性观察，不把鉴定规范的同一性结论移植到画像任务。

## 一致性与输出

运行 `scripts/validate_schemas.py` 验证示例契约，运行 `scripts/image_description.py <profile.json> --vision-attested --image-authorized` 复核已填充 Profile。若未确认视觉能力和授权，不传这两个开关，脚本只输出限制和 19 组件缺失状态。

输出包含图像质量、整体结构、19 组件、空间关系/不对称、提示词准备状态、绘画师简报和未采纳观察。`scripts/prompt_compiler.py` 是提前实现的图像任务 Phase 6 子集；用户反馈可通过 Profile 的 `prompt_focus` 记录观察 ID、关系 ID 和已见偏差。视角只用于内部观察质量判断，不进入生成提示词。本阶段不得声称已经生成图像。

`examples/facial_profile.valid.json` 是结构示例，包含占位资产 ID，不对应任何真实人物或照片。
